# 术语表（terminology）

本文件属于工具层，保存中文文档与代码注释中已批准的词级决定，供编辑查阅并由[术语检查脚本](<../scripts/lint_terms.py>)辅助扫描。其他文件不复制词表。组织与表达仍按[本体原则](<../SKILL.md>)判断，未收录的表达不因此自动合格。

先确认文本职责与语境，再应用词级决定；技术标识、正式引用、法律原文等按各自保留要求处理。自然语言中的明确用词问题须修正，不能为通过检查改变事实或把问题藏进代码格式。扫描用法、覆盖范围和结果解释见[工具说明](<./tools.md>)。

优先级（高到低）：领域覆盖表（用户自建）→ 直译修正表 → 通用黑话表 → 保留词表。同一词在多层出现时，以更高层为准。

变更流程：新增或修改条目及级别必须经用户决定。领域覆盖表记录用词、语境、例子与扫描级别；其余表按各表表头登记。批准后同步更新[术语检查脚本](<../scripts/lint_terms.py>)的内置词表，或按下一节生成项目扫描词表。

## 一、领域覆盖表（最高优先级，用户自建）

项目领域规则分为人工维护的批准记录和供脚本读取的扫描词表。批准记录是依据，扫描词表由其已批准条目生成，不另作决定。以下文件名是建议，可按项目目录调整。

### 批准记录：Markdown 表格

在项目的 `references/terminology-domain.md` 中记录条目，保留四项解释要素，并增加经用户批准的扫描级别：

| 词 | 规范表述 | 语境定义 | 反例 → 正例 | 级别 |
|---|---|---|---|---|
| （项目用词） | （规范中文表述） | （什么语境下出现、指什么） | 「原文例句」→「改写例句」 | error 或 warn |

`error` 表示有明确映射、必须替换；`warn` 表示需结合语境人工判断。级别与用词决定一起批准，待决定条目不进入扫描词表。

### 扫描词表：制表符分隔文本

从每个已批准条目提取「词、规范表述、级别」，保存为 UTF-8 文件 `references/terminology-domain.tsv`。每行三列，以真实制表符分隔，不写表头；语境与例子留在批准记录中。行格式如下，`<TAB>` 表示制表符，不是要写入的文字，级别填 `error` 或 `warn`：

```text
词<TAB>规范表述<TAB>级别
```

井号开头的行作为注释，空行忽略。批准记录有变化时，同步重新生成扫描词表，包括删除已移除的条目。

从技能目录运行时，将目标和项目路径替换为实际路径：

```text
python scripts/lint_terms.py <目标路径> --terms <项目路径>/references/terminology-domain.tsv
```

`--terms` 读取的是 TSV 扫描词表，不是 Markdown 批准记录。首次使用时，用一段含领域词的样例确认报告了预期的建议与级别；退出码为零不能单独证明项目规则已加载。扫描不会理解 Markdown 中的语境说明，匹配结果仍须按批准记录判断。

### 相关机制

- `--skip-path REGEX` 追加项目专属的跳过目录：扫描前所有路径先归一化为「/」分隔再匹配，Windows 下正则同样用「/」写，写反斜杠永不命中。
- 领域字面词先于构词模式命中并屏蔽该处，构词模式不再重报。项目常用词撞上内置 error 级构词族时，可经用户批准将该词登记为 warn，再同步到 TSV 扫描词表；仅在 Markdown 记录中增补不会改变扫描结果。

## 四、保留词表（不改）

阻塞（blocking）、落盘（写入磁盘）、manifest、digest、流水线、快照（snapshot）、自洽（self-consistent）。`checkpoint` 的保留方式、级别及解释要求见[逐词映射](<#逐词映射族外>)。

保留原词与是否提示是两件事。需要人工检查语境或解释是否充分的保留词以 warn 级别进入扫描词表；其余纯保留词不进入，脚本不报告。

项目专用的保留词（制度名、机制名、领域术语）登记到项目自建的领域覆盖表，不写进本表。

英文默认译成规范中文；可保留原文的词见本表与逐词映射的「保留英文」条目。脚本只扫词表内登记过的词，未登记的不报。
