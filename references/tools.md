# 文档编辑工具

本文件属于工具层。工具为[编辑方法](<./editing-method.md>)提供证据、修改和恢复手段，编辑结果仍按[本体原则](<../SKILL.md>)判断。

## 一、Git：让直接修改有可靠依据

Git 保存修订经过，让现行文档可以直接重写、合并和删除。使用它的重点是建立可比较的起点、审阅必要修改和保存结果，而不是增加一套手续。已有授权与可靠基线时，直接推进编辑，不为每次可恢复的修改重复询问。

### 修改前：确认范围，保存基线

在目标目录中检查仓库与工作状态。下面的路径和提交标识是占位内容，执行时换成已确认的对象。

```text
git rev-parse --show-toplevel
git status --short --branch
git diff -- <目标路径>
git diff --cached -- <目标路径>
```

复用包含目标的现有仓库。确实没有仓库且已获授权时，在确认的范围内初始化。核实将要修改的正文是否已由提交保护；未跟踪和被忽略的文件不出现在普通差异中，需要单独确认。

已有提交完整包含当前原文时，记下提交标识即可复用。用户要求单独保存现状，或原文存在未提交变化时，按授权保存基线。排除缓存、产物与敏感材料，只暂存确认属于本次保存范围的文件：

```text
git add -- <目标文件>
git diff --cached
git commit -m "保存文档编辑基线"
git rev-parse HEAD
```

提交包含暂存区的内容，因此先处理无关暂存项或同文件中的混合修改，不能把它们无意带入。需要修改但不宜提交的私有材料，使用经用户认可的可恢复备份。

区分阅读、编辑、备份、提交和发布的权限：不允许提交私有材料，不自动意味着禁止按已授权任务读取或整理。只确认实际缺失的保护方式或授权，已明确的事项不重问。

保护以原文已经保存且可恢复为准，认可备份方案或愿意承担损失都不等于已经保护；完成保存后即可编辑。某个文件还不能修改时，可以继续处理范围清楚、已受保护且不依赖它的内容。

### 编辑时：直接重写，用差异检查遗漏

有基线后，按文档需要修改，不以差异行数最少为目标。移动和删除可用 `git mv`、`git rm`；引用与符号链接仍需随之修正。

```text
git diff <基线提交> -- <目标路径>
git diff --check -- <目标路径>
```

重点核对有效要求是否遗漏、范围是否意外扩大、相关内容是否同步。新文件未暂存时单独阅读；修改后读回完整段落与必要上下文，不能只读差异行。追溯时可用 `git log`、`git blame` 和版本比较找依据，但提交较新不代表事实一定正确。

### 完成后：提交结果，提供比较位置

验证后按授权提交相关修改。纯移动和内容变化在便于审查时分开提交，不为形式拆成碎片。确认提交成功与工作状态，报告基线、结果提交及验证范围。

```text
git diff <基线提交> <结果提交> -- <目标路径>
```

比较版本无需切换或覆盖工作区。确需恢复时，先保护恢复范围内的新改动，再按授权恢复目标内容；局部问题不使用整仓覆盖。提交与本地恢复不等于授权推送或发布。

## 二、搜索：发现相关内容与引用

使用环境提供的文件发现、内容搜索和读取工具。按技术标识、旧值、相关名称、同义表述查找受影响内容；移动或删除时同时查文件名、路径片段、章节标识和导航引用。

搜索找到的是待判断位置。逐处读上下文，区分现行说明、条件差异和历史记录，再决定修改。没有命中提示词不表示没有冲突：分散在不同条目的相反结论也需要语义检查。

检查读者实际取得的文件及其链接，不只检查源码目录。无法访问或尚未检查的范围在交付中说明；搜索结果不另存成一份与正文争夺权威的事实总表。

## 三、术语表与术语检查

[术语表](<./terminology.md>)保存已批准的词级决定及领域覆盖规则，其他材料引用它，不复制词表。[术语检查脚本](<../scripts/lint_terms.py>)使用 Python 标准库，只报不改，不自动挂入项目准入检查。

需要术语清查时扫描受影响的完整范围，不仅扫描自己列出的替换清单。从技能目录运行，替换目标路径：

```text
python scripts/lint_terms.py <目标路径>
python scripts/lint_terms.py <目标路径> --terms <项目路径>/references/terminology-domain.tsv
python scripts/lint_terms.py <目标路径> --skip-path "(^|/)vendor(/|$)"
```

`--terms` 使用由已批准领域规则生成的 TSV 扫描词表，不使用 Markdown 批准记录；生成方法和加载确认见[术语表](<./terminology.md#一领域覆盖表最高优先级用户自建>)。`--skip-path` 按归一化后的正斜杠路径匹配正则表达式。

### 判断检查结果

`error` 按已批准规则修正，`warning` 逐项判断语境。误报先核实，通过规定的领域覆盖或用户决定处理；不为消除提示改坏语义或隐藏文本。

默认退出码 `0` 表示已扫描范围没有 error，仍可能有 warning；`1` 表示有 error，启用 `--strict` 时 warning 也会导致 `1`；`2` 表示参数、路径或词表读取等已识别的使用错误。读取异常或中途退出不算检查通过。

脚本默认跳过缓存、Git、依赖目录、脚本自身，以及名称匹配术语表、中文表达和代码注释附件的文件。Markdown 反引号围栏和行内代码也不扫描。直接传入命中跳过规则的文件仍不会扫描，相关内容须人工审读。

扫描使用近似语法提取，可能误识别字符串中的注释标记，也不能识别所有 Markdown 代码形式；具体范围见脚本头部。词表与构词模式只能发现部分已知问题，无 error 不证明事实、结构、语义或可读性合格。
